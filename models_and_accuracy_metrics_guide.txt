1.1 MODEL 1: UNIVERSAL BISENETV2 (SEMANTIC TRACK & RAIL LINE SEGMENTATION)
----------------------------------------------------------------------------------------------------
PyTorch Weights: models/RailDrishti_Seg_BiSeNetV2.pth (17.3 MB, ~3.49 Million Trainable Parameters)
Production ONNX: models/RailDrishti_Seg_BiSeNetV2.onnx (13.3 MB, Constant-Folded & Slimmed via onnxslim)
Input Tensor:    [Batch, 3, 512, 1024] (Normalized RGB / Active 850nm NIR)
Output Tensor:   [Batch, 3, 512, 1024] (Class 0: Background, Class 1: Track Bed, Class 2: Rail Lines)

• Why BiSeNetV2 (Bilateral Segmentation Network V2)?
  Standard semantic segmentation architectures (e.g., DeepLabV3+, HRNet) are too heavy for 60+ FPS
  real-time locomotive edge compute. Traditional lightweight networks sacrifice high-frequency spatial
  details (narrow steel rails disappearing at the horizon). BiSeNetV2 solves this with a two-pathway design:

  A) Detail Branch (Spatial Path):
     - Operates at shallow downsampling (1/8th scale max) with 128 feature channels.
     - Preserves rich spatial textures, narrow continuous rail lines, track gauge edges, and ballast boundaries.
  
  B) Semantic Branch (Context Path):
     - Rapidly downsamples features (1/32th scale) using Gather-and-Expansion (GE) bottleneck layers.
     - Contains a Context Embedding (CE) block with Global Average Pooling to capture wide contextual receptive
       fields (distinguishing railway corridors from parallel highways, platforms, and catenary lines).

  C) Bilateral Guided Aggregation (BGA) Layer:
     - Merges spatial high-res details from the Detail Branch with semantic context from the Semantic Branch.
     - Uses depthwise separable convolutions and sigmoid channel-attention gates for high-speed fusion.

  D) Booster Training Strategy vs. Lightweight Inference:
     - During Kaggle training, 4 auxiliary heads (aux2, aux3, aux4, aux5_4) injected deep gradients.
     - In production inference, auxiliary heads are pruned completely (0 FLOPs overhead), leaving a lean 3.49M parameter engine.

  E) Universal Dual Training (Zero Catastrophic Forgetting):
     - Trained jointly on a balanced multimodal distribution: 14,450 RailSem19 Locomotive Cab frames (75%)
       and 2,680 Indian Railways Infrastructure & Drone frames (25%) with 50% Active 850nm NIR Night simulation.


1.2 MODEL 2: DUAL-LAYER OBSTACLE & SABOTAGE DETECTION SUITE (YOLO11m)
----------------------------------------------------------------------------------------------------
Custom Weights:  models/RailDrishti_Det_YOLO11m.pt (40.5 MB)
Production ONNX: models/RailDrishti_Det_YOLO11m.onnx (80.8 MB, Slimmed via onnxslim)
Base Foundation: models/yolo11m.pt (40.7 MB)
Input Tensor:    [Batch, 3, 1024, 1024]
Target Resolution: 1024x1024 (Crucial for detecting distant micro-sabotage like thin iron rods at >150 meters)

• How YOLO11m Works:
  YOLO11m represents the state-of-the-art in real-time object detection:
  - C3k2 & C2PSA Backbone: Cross-Stage Partial network with Spatial Attention layers that isolate small foreground
    targets against complex track ballast backgrounds.
  - Anchor-Free Decoupled Head: Separates classification loss from bounding box regression loss.
  - Task-Aligned Assigner (TAL): Dynamically aligns classification confidence with box localization quality during training.
  - Distribution Focal Loss (DFL) + Complete IoU (CIoU): Penalizes aspect ratio and distance deviations for exact box grounding.

• The Dual-Layer Architecture:
  - Layer 1 (Custom Specialized Detector - RailDrishti_Det_YOLO11m.pt):
    Trained specifically for 8 high-risk railway threats: Person, Car, Truck, Branch, IronRod, Boulder, Barrel, Jerrycan.
    Excludes trains ('on-rails') to eliminate false alarms from parallel line traffic.
  - Layer 2 (Base Foundation Detector - yolo11m.pt):
    Runs 19 enabled complementary COCO classes for wildlife/livestock (Cow, Elephant, Horse, Dog, Cat, Sheep, Bear,
    Zebra, Giraffe), extra transport (Bus, Motorcycle, Bicycle), and debris/luggage (Suitcase, Backpack, Handbag, Bench, Umbrella).
  - Intelligent Fusion Layer:
    Performs IoU-based Non-Maximum Suppression (NMS) merging. Custom railway predictions take precedence, while
    unique foundation detections (e.g. cattle or luggage) are integrated into the hazard stream.


1.3 SUBSYSTEM 3: SPATIAL HAZARD & CLEARANCE REASONING (SHAPELY VECTOR ATP)
----------------------------------------------------------------------------------------------------
• Not a black-box neural net, but deterministic vector geometry:
  1. Computes the obstacle's bottom ground footprint: F_k = [x1, y2 - delta_h, x2, y2].
  2. Converts segmented Track Bed (Class 1) and Rail Lines (Class 2) masks into Shapely 2D Polygon objects.
  3. Computes vector polygon intersection and minimum Hausdorff / Euclidean distance:
     - 🔴 CRITICAL (In-Track): Intersection area(F_k ∩ Track_Poly) > 0. Immediate ATP emergency brake command.
     - 🟡 WARNING (Near-Track): Distance(F_k, Track_Poly) <= Warning_Buffer (65 px). Driver HUD caution alert.
     - 🟢 CLEAR (Off-Track): Distance > 65 px (e.g., pedestrian on platform or car on parallel road). No brake intervention.

2.1 SEMANTIC SEGMENTATION ACCURACY METRICS (BiSeNetV2)
----------------------------------------------------------------------------------------------------

A) Intersection over Union (IoU) / Jaccard Index per Class:
   • Formula:
     IoU_c = TP_c / (TP_c + FP_c + FN_c)
     where:
       - TP_c (True Positive):  Pixels correctly predicted as class c.
       - FP_c (False Positive): Pixels incorrectly predicted as class c (over-segmentation).
       - FN_c (False Negative): Pixels belonging to class c that were missed (under-segmentation).

   • Why it Matters:
     IoU measures the exact spatial overlap percentage between the model's predicted mask and human ground truth.
     For railways:
     - Track Bed IoU = 90.08%: The model captures 90%+ of the drivable gauge without spilling onto platforms.
     - Rail Lines IoU = 69.11%: High score for thin lines (narrow steel rails are only 3-5 pixels wide at horizon).

B) Mean Intersection over Union (mIoU):
   • Formula:
     mIoU = (1 / C) * SUM_{c=0}^{C-1} [ IoU_c ]
   • For Drishti-Kavach:
     mIoU = (IoU_Background + IoU_TrackBed + IoU_RailLines) / 3
     Our Universal Model achieves: 86.02% Universal mIoU.

C) Pixel Accuracy (PA):
   • Formula:
     PA = Total Correctly Classified Pixels / Total Pixels in Image = SUM(TP_c) / Total_Pixels
   • Our Model achieves: 98.86% Pixel Accuracy.
   • Note on PA: Because Background occupies ~80% of pixels, PA is naturally high; mIoU is the true gold standard.

D) Mean Pixel Accuracy (MPA) / Class Recall:
   • Formula:
     MPA = (1 / C) * SUM [ TP_c / (TP_c + FN_c) ]
   • Measures what percentage of each ground truth class was successfully recognized.

E) Dice Coefficient / F1-Score:
   • Formula:
     Dice_c = (2 * TP_c) / (2 * TP_c + FP_c + FN_c) = 2 * IoU_c / (1 + IoU_c)
   • Our Model achieves: 91.24% Mean Dice Score.


2.2 OBJECT DETECTION ACCURACY METRICS (YOLO11m)
----------------------------------------------------------------------------------------------------

A) Precision (P):
   • Formula:
     Precision = TP / (TP + FP)
   • Meaning: "When the detector claims there is an obstacle, how often is it actually an obstacle?"
   • Railway Impact: High precision prevents false emergency brake applications (which disrupt train schedules).

B) Recall (R):
   • Formula:
     Recall = TP / (TP + FN)
   • Meaning: "Out of all actual obstacles on the tracks, how many did the detector successfully find?"
   • Railway Impact: High recall is critical for safety—missing a steel rod or boulder (False Negative) can cause derailment.

C) Average Precision (AP) per Class:
   • Calculated as the Area Under the Precision-Recall (PR) Curve for a given IoU threshold:
     AP = INTEGRAL_{0}^{1} p(r) dr
   • Evaluates how well the model balances Precision vs Recall across all confidence thresholds (0.0 to 1.0).

D) mAP@50 (Mean Average Precision at IoU = 0.50):
   • A detection is counted as a True Positive if the predicted box overlaps the ground truth box by >= 50% IoU.
   • mAP@50 is the average AP across all classes at this 0.50 cutoff.
   • Our Model achieves: 60.8% Overall mAP@50 (with 90.9% for IronRod, 78.4% for Barrel, 77.5% for Jerrycan).

E) mAP@50-95 (COCO Primary Benchmark):
   • The average mAP computed across 10 progressive IoU thresholds: [0.50, 0.55, 0.60, ..., 0.90, 0.95].
   • Measures bounding box tightness and edge localization precision.
   • Our Model achieves: 38.4% mAP@50-95.

3.1 DO ACCURACY METRICS CHANGE ACROSS HARDWARE (CPU vs CUDA GPU vs MPS vs TENSORRT)?
----------------------------------------------------------------------------------------------------
• Mathematical Precision (FP32 vs FP16 vs INT8):
  1. Standard FP32 (Single Precision Float):
     Running inference on an Intel/AMD CPU, Apple Silicon GPU (MPS), or NVIDIA Tesla GPU (CUDA) in FP32
     produces VIRTUALLY IDENTICAL METRICS (differences are <= 0.001% due to minor hardware floating-point rounding).
  
  2. FP16 (Half Precision / Automatic Mixed Precision):
     On NVIDIA Tensor Cores or Apple Neural Engine, FP16 halves memory bandwidth and doubles speed.
     mIoU and mAP vary by less than 0.1% to 0.2% compared to FP32—completely negligible for safety.

  3. INT8 Quantization (8-Bit Integer Edge Deployment):
     If quantized to INT8 (via TensorRT or ONNX Runtime for embedded NVIDIA Jetson), there is a minor
     accuracy drop (~0.8% to 1.5% mAP), but inference speed increases by 3x to 4x.

• Dynamic Resolution (imgsz):
  - Running YOLO at imgsz=640 drops micro-obstacle detection (IronRod drops from 90.9% to ~72%).
  - Running YOLO at imgsz=1024 (our standard) preserves fine steel sabotage items at distance.

• Camera Sensor & Environmental Variation:
  - Daylight RGB vs Active 850nm NIR Night: Our models were trained with 50/50 day/night data, maintaining
    >85.8% mIoU under night headlights compared to 86.1% in broad daylight (less than 0.3% gap!).
